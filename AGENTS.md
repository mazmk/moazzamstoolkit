# AGENTS.md

Instructions for AI coding agents (and humans) working on **Moazzam's Toolkit** — a collection of small browser tools. Everything runs client-side; nothing is uploaded. Read this before changing code.

## Commands

| Command | Use |
| --- | --- |
| `pnpm install` | Install (Node 22, see `.nvmrc`) |
| `pnpm dev` | Dev server |
| `pnpm lint` | ESLint — must be clean, warnings included |
| `pnpm typecheck` | `tsc -b` for app, build plugin and config |
| `pnpm test --run` | Vitest once. Plain `pnpm test` is watch mode and never exits |
| `pnpm check:contrast` | WCAG AA check of every token pair — run after touching colors |
| `pnpm build` | Production build (also generates SEO pages, sitemap, robots, llms files) |
| `pnpm generate:images` | Re-render link-preview cards + app icons (needs local Chrome) |
| `npx prettier --write src build scripts` | Format (Prettier sorts Tailwind classes) |

**Definition of done** for any change: lint, typecheck, `test --run` and build all pass; `check:contrast` passes if colors changed; new behaviour has tests; docs and generated metadata are updated (see the checklist below).

## Architecture

```
src/app/toolMeta.ts      Plain data: site + every tool's name, path, copy, SEO, capabilities, limits.
                         No React — it's also imported at build time and by scripts.
src/app/tools.ts         The registry: toolMeta + icon + lazy page component.
src/app/router.tsx       Routes generated from the registry. Never hardcode a route list elsewhere.
src/app/Layout.tsx       Floating navbar, page fade, footer, per-page title/description/canonical.
src/features/<tool>/     components/ (UI) · lib/ (logic, hooks, pure helpers + tests)
src/shared/ui/           Shared components — use these before writing new ones.
src/shared/hooks|lib/    Shared hooks and helpers (object URLs, media queries, formatting).
src/styles/tokens.css    Every design token, both themes.
build/seo.ts             Vite plugin: <head> meta, per-tool HTML pages, 404, sitemap, robots, llms.
scripts/                 check-contrast.mjs, generate-images.mts.
public/og, public/icons  Generated images (committed; CI doesn't have Chrome).
```

Routes, the home index, the Tools menu, the ⌘K palette, the static SEO pages, sitemap, manifest shortcuts, `robots.txt`, `llms.txt` and `llms-full.txt` are **all generated from `toolMeta.ts` + `tools.ts`**. If you find yourself listing tools by hand anywhere, stop and derive it from the registry instead.

## Adding or changing a tool — checklist

Do all of these in the same change:

1. **Feature folder** `src/features/<tool>/` with a default-exported page in `components/` and logic in `lib/`.
2. **`src/app/toolMeta.ts`** entry: `id`, `name`, `description` (one line), `path`, `category`, `keywords`, `seoTitle` (short — it's `<title>` and `og:title`), `seoDescription` (~150 chars), `capabilities` and `limits`.
   - `capabilities` / `limits` feed `llms-full.txt`, which AI assistants use to answer questions about the tool. Keep them **true and specific** — state real limits (file sizes, unsupported inputs, browser requirements). Never claim something you haven't verified (e.g. browser support you didn't test).
3. **`src/app/tools.ts`** UI entry: icon + `lazy(() => import(...))`. Keep it lazy so the tool's dependencies load only on its page.
4. **Preview card**: `pnpm generate:images` → commit `public/og/<id>.png`. Re-run whenever a tool's name, description or the brand changes.
5. **Tests** for the tool's pure logic (`lib/*.test.ts`); the registry and SEO tests cover metadata completeness automatically.
6. **README** — the tools table and anything structural.
7. **Verify**: `pnpm build`, then check `dist/<path>/index.html` has the right title, description and `og:image`, and the tool appears in `dist/sitemap.xml`, `dist/llms.txt` and `dist/llms-full.txt`.

Renaming a path? Old links will 404 — mention it in the PR. Changing what a tool does? Update its `capabilities` / `limits` so `llms-full.txt` stays accurate.

## SEO, link previews and AI crawler files

Scrapers and AI crawlers don't run JavaScript, so all of this is static HTML/text generated by `build/seo.ts`:

- **Never hand-edit** generated output in `dist/`, and don't add meta tags directly to `index.html` — it only has a `<!-- seo -->` marker. Change `toolMeta.ts` (copy) or `build/seo.ts` (structure).
- `robots.txt` allows everyone and names AI crawlers in `AI_AGENTS`. Add new crawler user-agents there; don't add `Disallow` rules without the owner's say-so.
- `llms.txt` / `llms-full.txt` follow [llmstxt.org](https://llmstxt.org). New site-wide facts (privacy, requirements) go in `renderLlmsTxt` / `renderLlmsFullTxt`; per-tool facts go in `toolMeta.ts`.
- Absolute URLs come from `SITE_URL` (set in CI from the Pages URL). Don't hardcode the domain in components.
- Keep `pageTitle()` as the single source for titles, so the static HTML and the running app agree.

## Design system — rules

Direction: "workshop bench / editorial tool index" — warm paper, ink type, one hot accent, flat surfaces, hairline borders, mono details.

- **Tokens only.** Colors, radii, fonts and easing come from `src/styles/tokens.css` via Tailwind utilities (`bg-paper`, `bg-surface`, `bg-surface-2`, `text-ink`, `text-muted`, `border-line`, `bg-accent`, `text-accent-text`, `rounded-control`, `rounded-panel`, `font-display/sans/mono`, `ease-out`). No raw hex values or arbitrary colors in components. Need a new color? Add a token for **both themes**, then run `pnpm check:contrast`.
- **Accent use:** `--accent` is for fills, borders, icons and large text only. Small accent text uses `--accent-text`. Text on an accent fill uses `--accent-ink`.
- **Selected state** (chips, segmented, choice cards) is ink-filled with paper text — never accent.
- **Surfaces:** page content goes in `<Panel>` (solid surface, 1px line, 14px radius, no blur, no shadow). `glass-float` is **only** for things floating above content: navbar, command palette, dropdowns, recorder control bar, toasts. Never a page or panel surface.
- **Never:** gradients (buttons, icons, text, backgrounds), purple/indigo/violet, glow or decorative shadows, blurred blobs, card-inside-card nesting, centered heroes.
- **Radii:** 10px controls, 14px panels, 999px only for chips, switches and the navbar pill.
- **Type:** Instrument Serif (`font-display`) only for the home headline and page titles; Geist for UI; JetBrains Mono for labels, indexes, shortcuts, timers, sizes and percentages. Category labels: uppercase 11px mono, `tracking-[0.06em]`.
- **Motion:** 120–180ms `ease-out`, mechanical (no bounce/scale). Presses use `translate-y-px`. Respect `prefers-reduced-motion`; glass falls back to solid under `prefers-reduced-transparency`.

## Shared components — use before building

`src/shared/ui/`: `Panel`, `Button` (primary · secondary · ghost · danger), `Tag`, `TextField`, `Chip`, `Segmented`, `Menu` (menu-button pattern, portalled), `Toast` (`toast(message, tone)`), `ProgressBar`, `FileDropzone`, `SplitPane`, `InlineError`, `PageHeader` (`toolId` derives the "TOOL 03 / VIDEO" eyebrow), `Backdrop`, plus `ConfirmDialog` in `src/shared/components/`.

- Start every tool page with `<PageHeader toolId="…" title="…" description="…" />`.
- Add a new shared component only when a second feature needs it; keep feature-specific UI in the feature folder.
- Prefer **props over className overrides** for variants (e.g. `Tag tone="accent"`, `Button size="xl"`). Tailwind doesn't guarantee order between a component's classes and an override on the same property, so overrides like `h-16` on a `size="lg"` button are a bug waiting to happen.

## Code conventions

- **TypeScript strict.** No `any`, no `as never`/`as unknown as` to silence types — use the library's exported types.
- **Logic out of components.** Hooks and pure helpers live in `lib/`; components stay presentational and small. Pure helpers get unit tests next to them (`*.test.ts`).
- **Lazy-load heavy dependencies** (ffmpeg, markdown, muxers) — inside the tool's page or via dynamic `import()` at the point of use.
- **State:** Zustand stores for cross-component state; `localStorage` access always wrapped in `try/catch` (private mode and blocked storage throw). Persisted keys are prefixed `toolkit:` — except legacy `screennest:*` keys and the `screennest` IndexedDB name, which **must not be renamed** (that would wipe users' recordings and settings).
- **Effects:** no synchronous `setState` in effects; derive during render or use the "adjust state on change" pattern. Clean up object URLs (`useObjectUrlRef`), timers, workers and listeners.
- **Accessibility is required, not optional:** keyboard access for everything, `aria-label` on icon-only buttons, visible focus ring (global 2px accent outline — don't remove outlines without a replacement), `aria-live` for progress/status, radiogroup semantics with roving tabindex for segmented choices, native `<dialog>` for modals.
- **Privacy is the product:** never send user data anywhere. New network requests (CDNs, analytics, fonts) need the owner's approval; fonts and wasm are self-hosted.
- Match the surrounding code style and comment density; comments explain *why*, not *what*.

## Gotchas (each of these has bitten this repo)

- **Lightning CSS drops a standard `backdrop-filter` that's followed by `-webkit-backdrop-filter`.** Always write the prefixed declaration first. Dev mode doesn't minify, so this only breaks production — verify with `pnpm build`.
- **A `filter` (even `blur(0)`) or `opacity < 1` on an ancestor makes it a backdrop root** and kills blur on glass inside it. Page transitions use opacity/transform only.
- **`@theme inline` self-references** (`--font-mono: var(--font-mono)`) create a cycle. Source tokens use different names (`--font-code`, `--panel-radius`, …).
- **Don't nest backdrop-filters**; floating panels portal to `<body>` (a blurred parent also becomes the containing block for `position: fixed`).
- **`getDisplayMedia` needs a recent user gesture** (Safari allows ~1s) — don't put delays before calling it.
- **ffmpeg.wasm** is the single-threaded core (no COOP/COEP); it's excluded from `optimizeDeps` so its worker URL survives in dev.
- **Contrast:** darkening a fill under dark text *lowers* contrast — check hover states, not just resting ones.
- **jsdom** lacks `<dialog>.showModal` and `URL.createObjectURL`; minimal polyfills live in `src/test/setup.ts`.

## Keeping docs current

When a change affects any of the following, update it in the same change:

- `README.md` — tools table, structure, commands.
- `AGENTS.md` (this file) — new conventions, components, commands or gotchas you discovered.
- `toolMeta.ts` copy, `capabilities` and `limits` — which regenerate SEO pages, sitemap, `llms.txt` and `llms-full.txt` on the next build.
- `public/og/*.png` — via `pnpm generate:images` when names, descriptions or branding change.
